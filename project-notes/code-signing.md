# Code Signing (Optional Release Hardening)

This guide describes a non-blocking Authenticode signing path for Windows release artifacts.

## Why sign binaries

- Improves trust signals for users and enterprise environments.
- Reduces SmartScreen friction for distributed executables.
- Provides tamper-evidence via signature verification.

## Signing model

- Keep signing optional for local development.
- Sign only release artifacts generated by `dev/release-package.ps1`.
- Do not store private certificates in source control.

## Prerequisites

- Windows SDK `signtool.exe` available on the signing machine.
- Valid code-signing certificate (preferably EV for public distribution).
- Timestamp service URL (required to keep signatures valid after cert expiry).

## Recommended workflow

1. Generate release package:

```powershell
.\dev\release-package.ps1
```

2. Sign executables in `artifacts/publish/win-x64/`:

```powershell
$certThumbprint = "<thumbprint>"
$timestampUrl = "http://timestamp.digicert.com"
$publishDir = ".\artifacts\publish\win-x64"

Get-ChildItem $publishDir -Filter *.exe | ForEach-Object {
  signtool sign `
    /sha1 $certThumbprint `
    /fd SHA256 `
    /tr $timestampUrl `
    /td SHA256 `
    /d "Sir Thaddeus" `
    /v $_.FullName
}
```

3. Verify signatures:

```powershell
Get-ChildItem ".\artifacts\publish\win-x64" -Filter *.exe | ForEach-Object {
  signtool verify /pa /v $_.FullName
}
```

4. Rebuild the distributable archive and checksums after signing:

```powershell
.\dev\release-package.ps1 -SkipPreflight
```

## Operational safeguards

- Restrict certificate access to designated release operators.
- Prefer hardware-backed key storage when available.
- Rotate certificates before expiry and update timestamp endpoints as needed.
- Keep signature verification in the release checklist.

## CI integration (future)

If signing is moved into CI:

- Use protected secrets and environment approvals.
- Isolate signing jobs from normal PR validation jobs.
- Require manual approval for signing workflows.
